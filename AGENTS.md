# Architecture rules
- Share the selected local delivery between cart and checkout through DeliveryProvider; one consultation prevents diverging address and freight states.
- Keep monetary and served-city rules in checkoutRules with concrete unit tests; unknown freight must remain null.
- Keep the owner-defined road-distance tariff in checkoutRules and server freight-quote; local-route-freight signs address-bound, expiring raw route metres using an existing server-only secret, and both payment functions verify the signature and recalculate freight, products, stock and coupons before orders or charges. Browser delivery.price stays null and browser totals never authorize an amount.
- Use shared server payment-pricing and validated-payment for both Mercado Pago endpoints; canonical adjustment lines keep order/PDF totals consistent and changed totals require another customer confirmation.
- Verify order reference and approved status through the existing read-only order lookup before displaying payment success; URL status is never proof.
- Send all ecommerce events through src/lib/analytics.ts; purchase only from confirmedPurchase, once per transaction_id, and every destination stays disabled until real IDs and a consent integration are configured, so no unverified or non-consented sale is reported.- Route quotes go through src/lib/routeQuote.ts (null on failure, never an invented price); WhatsApp is support-only and never creates or finalizes orders, so every sale passes through the verified Pix checkout.
- Images render through ResponsiveImage with versioned WebP variants: local /products photos (public/products/opt, localImageVariants.ts) and exact known public store URLs (public/products/opt-remote, remoteImageVariants.ts); stored originals are never rewritten and unknown URLs render as-is, so originals stay the fallback.
